# v1.1.3 unique subscription node names

Date: 2026-06-09

## Scope

Small release to fix duplicate proxy names in final subscription output, especially before Clash / Clash Verge conversion.

No Docker, deployment, reverse proxy, data, logs, `.env`, database cleanup, or Telegram Bot flow changes.

## Fix

- `node_processor.py`
  - Added `clean_node_name()`.
  - Added `truncate_node_name()`.
  - Added `unique_node_name()`.
  - `processed_nodes()` now cleans, truncates, and deduplicates every generated output name.
  - Duplicate names become:
    - `free-nodes`
    - `free-nodes #2`
    - `free-nodes #3`

- `web_app.py`
  - `subscription_output()` now builds processed rows once and uses those renamed URIs for Base64, raw, and every Sub-Store conversion target.
  - The admin subscription converter non-custom path also sends processed renamed URIs to Sub-Store.

- `app_version.py`
  - Version bumped to `v1.1.3`.

## Output entries protected

- Public token subscription Base64.
- Public token raw / V2RayN-style output.
- Public token Clash / Clash Verge, Sing-box, Surge, Shadowrocket conversion input.
- Admin converter when using the stored subscription pool as input.

## Tests

Added tests for:

- Two or more duplicate names receiving stable `#2`, `#3` suffixes.
- Long names being capped to 80 characters.
- Clash Verge conversion input receiving unique node names before conversion.

Commands to run:

```text
python -m py_compile app_version.py node_processor.py web_app.py
python -m unittest test_node_processor test_web_app -v
python -m unittest discover -v
```

## Risk

- Cached converted subscriptions created before this release may still contain duplicate proxy names. Clear subscription conversion cache after deployment.
- If a custom Sub-Store conversion is fed by user-provided custom content, the app does not rewrite that custom text.

## Rollback

Switch back to `codex/v1.1.2-release` or tag `v1.1.2`.
