## 本版重点

- 默认订阅池只发布亚洲优先、美国补充的节点。
- 默认排除欧洲、非洲、未知地区节点进入订阅池。
- 排除只是订阅池筛选，不删除数据库里的节点。
- 不改 Docker、宝塔/Nginx、Telegram Bot 主领取流程、运行数据和环境变量。

## VPS 更新前备份

在 VPS 项目目录执行：

```bash
cd /www/wwwroot/node.huage.us
tar -czf huage-data-backup-$(date +%F-%H%M)-before-v1.1.0.tar.gz data
```

如果当前目录不是 `/www/wwwroot/node.huage.us`，先切到实际部署目录。

## 拉取 v1.1.0

推荐固定到标签：

```bash
cd /www/wwwroot/node.huage.us
git fetch origin
git fetch --tags
git checkout v1.1.0
```

如果要跟随发布分支：

```bash
cd /www/wwwroot/node.huage.us
git fetch origin
git checkout codex/v1.1.0-release
git pull origin codex/v1.1.0-release
```

## Docker Compose 部署重启

```bash
cd /www/wwwroot/node.huage.us
docker compose up -d --build
docker compose ps
```

## 宝塔 Python 项目方式

如果 Web 是宝塔 Python 项目管理器运行：

```bash
cd /www/wwwroot/node.huage.us
source .venv/bin/activate
pip install -r requirements.txt
```

然后在宝塔面板重启 Python 项目。

Sub-Store 仍需单独保持 `127.0.0.1:3001` 可访问；本版本没有改 Sub-Store 部署方式。

## 启动后检查

```bash
curl http://127.0.0.1:8765/healthz
curl http://127.0.0.1:3001
```

后台地址：

```text
https://你的域名/adminhuage
```

后台重点检查：

- 自动总控是否开启。
- 有效节点数量是否正常。
- 订阅转换页 Sub-Store 健康检查是否通过。
- 新生成的订阅是否能返回节点。
- 订阅池是否不再默认包含欧洲、非洲、未知地区节点。

## 快速验收命令

只测领取和订阅转换，不触发采集/验证：

```bash
python e2e_acceptance_runner.py --skip-collect --skip-validate --claim-rounds 5 --claim-rate-per-minute 30
```

小流量完整链路验收：

```bash
python e2e_acceptance_runner.py --smoke --claim-rounds 5 --claim-rate-per-minute 30 --poll-seconds 10
```

## 回滚

保留数据，回到 `v1.0.0`：

```bash
cd /www/wwwroot/node.huage.us
git fetch --tags
git checkout v1.0.0
docker compose up -d --build
```

如果是宝塔 Python 项目方式，切回标签后在宝塔面板重启项目。

## 注意事项

- 本版本不会保证免费节点 100% 可用，只是默认筛选更适合国内用户的地区。
- 不要把 `8765` 和 `3001` 直接暴露到公网。
- 不要提交或覆盖 VPS 上的 `data/`、`.env`、运行日志。
- VPS 首次或重装后仍需准备 Linux 版 Xray：`tools/xray/xray`、`geoip.dat`、`geosite.dat`。
