# v1.1.5 Collector / Validator Cleanup

Date: 2026-06-10
Branch: codex/v1.1.5-collector-validator-cleanup

## Scope

This release only optimizes collector scanning, validator logging, node URI redaction, and per-round summaries.

## Deployment Safety

- Did not modify VPS deployment configuration.
- Did not modify `data/`, `logs/`, `.env`, or `docker-compose.yml`.
- Did not modify Caddy, DNS, HTTPS, reverse proxy, or certificate configuration.
- Did not modify Telegram Bot claiming flow, payment, membership, or admin login logic.

## Collector Changes

- Capped effective GitHub tree depth at 3 even if a larger depth is passed by configuration.
- Expanded low-value directory skipping for assets, images, icons, css, js, pages, docs, tests, builds, and selected `src` utility/settings/content paths.
- Preserved high-value `src` paths when names include subscription/proxy/protocol keywords.
- README files are only parsed when content contains node URI protocol hints.
- Collection-stage region filtering is now softer: advertising and explicitly excluded regions are rejected, while unknown nodes may enter the pending pool for validation.
- Added collector summary counters for repositories, directory pages, raw files, skipped directories, candidate files, parsed nodes, inserted nodes, duplicates, region rejected count, failed sources, and elapsed seconds.

## Validator Changes

- Validator output no longer prints full `vmess://`, `vless://`, `trojan://`, `ss://`, or `ssr://` links.
- Node log output uses protocol, host, port, and a short hash summary.
- Common invalid-node results are classified as business failures, not program errors.
- Added validation summary counters for batch size, valid, invalid, timeout, TLS errors, connection resets, parse errors, exceptions, new valid nodes, elapsed seconds, and exit code.

## Runtime Log Changes

- Dashboard task log level classification now treats normal invalid nodes as warnings.
- Hard errors remain errors for Xray missing, geo data missing, database errors, tracebacks, exceptions, and startup/write failures.

## Validation Plan

- Python syntax checks for app/version, web app, collector, region, database, geoip, and validator modules.
- Frontend syntax check for `web/app.js`.
- Full unit test discovery.
- Targeted collector, validator, and runtime task tests.
