# v1.1.8 发布池隔离 + 人工验收发放

日期：2026-06-10

## 范围声明

- 本次没有修改 VPS 部署配置。
- 本次没有修改 data/logs/.env/docker-compose.yml。
- 本次没有修改 Caddy/DNS/HTTPS。
- 本次修复的是发布池隔离和人工验收，不是采集扩源。

## 背景

premium_subscription_pool 只能代表 VPS 视角的候选质量，不能代表粉丝本地真实可用。为避免 Bot 直接把未人工验收的候选节点发给粉丝，本版本新增独立发布池，要求后台人工确认可用后才允许进入订阅输出。

## 改动摘要

1. 新增 publish_subscription_pool 表，保存人工标记的可发布节点。
2. Bot 领取成功前检查发布池数量；发布池为空时不创建订阅链接。
3. 最终订阅输出改为只读取发布池，不再从 premium_subscription_pool 兜底输出。
4. 订阅访问日志新增 source 和 export_count 字段，成功访问记录 source=publish_pool。
5. 后台订阅页新增候选节点验收区，可标记可发布、不可发布、移出发布池、清空发布池。
6. 发布池展示只显示协议、地区、server、port、network、TLS、VPS 验证状态等脱敏信息，不展示完整节点链接。

## 发布池规则

- premium_subscription_pool 只作为候选池。
- publish_subscription_pool 是唯一粉丝订阅输出来源。
- 发布池为空时，Bot 返回：“本批免费节点正在筛选中，暂时没有可发放节点，请稍后再试。”
- 输出前仍沿用最终过滤、地区规则和节点名称去重。
- xhttp、tuic、hysteria、hysteria2、缺少 server/port/uuid 的节点默认不能标记为可发布。

## 验收建议

1. 后台进入订阅分发中心，查看“人工发布池”数量。
2. 从优质候选池选择节点，本地客户端测试 Google / YouTube。
3. 确认可用后点击“标记可发布”。
4. 用 Bot 领取订阅，客户端删除旧订阅后重新导入。
5. 检查订阅访问日志包含 source=publish_pool 和 export_count。
