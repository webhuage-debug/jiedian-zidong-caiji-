# v1.1.1 Final Subscription Filter Fix

Date: 2026-06-09

## Scope

- Added a final subscription filtering module.
- Applied the same final filter to raw, Base64, and Sub-Store converted subscription outputs.
- Tightened publishable regions and excluded Europe, Africa, unknown regions, India, Indonesia, Russia, Turkey, Middle East, South Asia, and Telegram advertising-style nodes.
- Kept collection, Xray validation, Docker, deployment, Sub-Store configuration, data files, logs, and Telegram Bot claim flow unchanged.

## Final Output Rules

- Strong priority: HK, JP, SG, TW, KR.
- Second priority: US.
- Fallback priority: MY, TH, PH, VN.
- Default excluded: Europe, Africa, unknown, IN, ID, RU, TR, Middle East, South Asia, Telegram ad/channel naming.
- Default target output count is 30.
- Minimum safe count is 15.
- Maximum output count is 80.

## Implementation Notes

- `node_region.py` owns region and advertising-name classification.
- `subscription_filter.py` owns final publishable filtering, output count normalization, and sort order.
- `node_database.py` uses the final filter during premium subscription pool generation and export.
- `web_app.py` applies a second final filter immediately before raw, Base64, and Sub-Store conversion content is generated.
- If a new filtered pool would contain fewer than 15 nodes, old premium-pool nodes that still pass the whitelist are retained instead of blindly clearing the pool.
- Existing database rows are not deleted.

## Cache Behavior

- Conversion cache identity is based on the filtered node content.
- After this change, old conversion cache entries generated from unfiltered content will not match the new filtered content hash.
- To force immediate rebuild on VPS, clear the subscription conversion cache from the backend or restart and generate a new subscription response.
