# v1.1.15 Publish Center Dedupe UX

## Scope

- Optimized the admin publish center into a clearer workbench.
- Kept the v1.1.14 publish center APIs and refined their counting and dedupe behavior.
- Split the node management area into clearer views:
  - publish center
  - currently published
  - ready to publish
  - valid node inventory
  - disabled nodes
- Kept the publish center as a summary-first view instead of rendering all inventory lists at once.

## Dedupe And Counting

- Published nodes are deduped by node reference / fingerprint within the published view.
- Ready nodes are deduped by node reference / fingerprint within the ready view.
- Ready nodes exclude already published nodes and disabled nodes.
- Summary published and ready counts are based on the same backend list builders used by the list APIs.
- Publish center API list payloads return `node_ref` for operations and do not expose full node URI by default.

## Safety Notes

- This release did not modify VPS deployment configuration.
- This release did not modify `data/`, `logs/`, `.env`, or `docker-compose.yml`.
- This release did not modify Caddy, DNS, HTTPS, Nginx, or systemd configuration.
- This release did not modify `tools/xray/**`.
- This release did not modify the Bot delivery source.
- Bot still reads only from `publish_subscription_pool`.
- `/sub/<token>` still exports only from `publish_subscription_pool`.
- This release only optimizes admin publish center dedupe and UX. It does not change delivery rules.

## API Notes

- Reused existing endpoints:
  - `GET /api/publish-center/summary`
  - `GET /api/publish-center/published`
  - `GET /api/publish-center/ready`
- Mutating endpoints still accept legacy `uri` payloads and now also accept `node_ref` for publish center operations.

## Tests

- Updated database tests for summary/list count consistency.
- Updated web tests to verify publish center APIs do not return full URI by default.
- Updated web tests to verify `node_ref` can be used to mark nodes as publishable.
