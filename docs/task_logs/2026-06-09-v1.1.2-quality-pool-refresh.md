# v1.1.2 quality pool refresh

Date: 2026-06-09

## Scope

- Added visible app version metadata for the admin dashboard.
- Added collection-stage candidate filtering before pending nodes are inserted.
- Changed subscription and valid-node ordering from hard Asia-first latency sorting to mainland-friendly weighted quality scoring.
- Kept final subscription output on the existing cached/premium-pool path. Fan subscription access still does not trigger real-time validation.

## Version display

- `app_version.py` defines `APP_VERSION = "v1.1.2"`.
- `web_app.py` exposes version metadata in `/api/status` and `/healthz`.
- `web/app.js` updates the dashboard title to `华哥节点总控仪表盘 v1.1.2` when status is loaded.

## Collection-stage filtering

Implemented in `node_collector.DatabaseNodeSink.consume()` through `node_region.is_collection_candidate()`.

Allowed candidates:

- HK, JP, SG, TW, KR
- US
- MY, TH, PH, VN

Rejected before pending-pool insert:

- Europe, Africa, RU, TR, IN, ID, Middle East, South Asia
- unknown / unrecognized region
- Telegram / channel / ad-style nodes

This does not delete existing database rows. It only prevents newly collected low-value candidates from entering the pending validation pool.

## Quality scoring

Implemented in `subscription_filter.subscription_quality_score()`.

The new order weakens London VPS latency as a deciding factor:

1. publishable region weight
2. validation count / historical stability
3. VPS latency as a weak signal
4. high-latency penalty
5. recency and URI tie-breakers

This allows a fast US node to rank above a clearly slow Asian node, while still giving HK / JP / SG / TW / KR a strong fit bonus.

## Premium pool refresh

Implemented in `node_database.refresh_premium_subscription_pool()`.

- Builds the premium pool from final publishable candidates.
- Selects by weighted quality score.
- Tries lower-latency candidates first, then relaxed candidates if needed.
- Keeps the existing publishable premium pool when a refresh cannot reach the safe minimum.

## Risk

- Strict collection filtering can reject nodes whose names do not expose a recognizable region, even if they might work in China.
- The system still cannot perfectly simulate mainland networks from a London VPS. This release reduces the bias but does not eliminate it.
- Existing cached conversion output should be cleared on VPS after deployment when doing a clean rebuild.
