# v1.1.9 有效节点手动管理 + CF 候选补源

日期：2026-06-11

## 范围声明

- 本次没有修改 VPS 部署配置。
- 本次没有修改 data/logs/.env/docker-compose.yml。
- 本次没有修改 Caddy/DNS/HTTPS。
- 本次新增有效节点手动管理功能。
- 手动添加节点不会绕过发布池。
- 手动删除 / 禁用节点会同步影响优质池和发布池。
- 本次加入 CF / 混合免费节点候选源和 CF 候选识别。

## 改动摘要

1. 后台有效节点页新增批量粘贴导入区，支持一行一个 vmess/vless/trojan/ss/ssr 原始节点。
2. 手动导入节点进入“有效节点”表，标记 manual_added=1、source_type=manual，不自动进入 publish_subscription_pool。
3. 新增 manual_blocked_nodes 表，按节点指纹记录手动禁用/删除节点，防止再次进入有效池、优质池和发布池。
4. 有效节点表兼容新增 node_fingerprint、source_type、manual_added、manual_disabled、manual_note、disabled_at、disabled_reason、cf_candidate 字段。
5. 有效节点列表新增脱敏展示字段：server、port、network、tls、source_type、manual_added、cf_candidate、是否已发布。
6. 有效节点列表新增操作：标记可发布、移出发布池、移出优质池、禁用、删除。
7. 禁用或删除有效节点时同步移出 premium_subscription_pool、publish_subscription_pool，并清空 subscription_conversion_cache。
8. 发布池输出规则保持不变，Bot 仍只从 publish_subscription_pool 输出；发布池为空仍返回“本批免费节点正在筛选中，暂时没有可发放节点，请稍后再试。”

## 接口

- POST /api/valid-nodes/manual-import
  - 参数：nodes、note
  - 返回：added_count、duplicate_count、invalid_count、invalid 明细

- POST /api/valid-nodes/disable
  - 参数：uri、reason
  - 动作：写入 manual_blocked_nodes，禁用有效节点，移出优质池/发布池，清空转换缓存

- POST /api/valid-nodes/delete
  - 参数：uri、reason
  - 动作：写入 manual_blocked_nodes，删除有效节点，移出优质池/发布池，清空转换缓存

- POST /api/valid-nodes/remove-premium
  - 参数：uri
  - 动作：移出优质池并清空转换缓存
